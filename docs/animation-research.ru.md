# Анимации и перенос: исследование для Return Launchpad

Дата проверки: 10 сентября 2026 года. Исследованы исходная реализация `ContentView.swift`, `DragSessionManager.swift` и план аудита. Документ описывает выбор подхода; наличие рекомендации здесь не означает, что сценарий уже реализован или проверен на устройстве.

## Решение

Использовать готовый движок анимаций Apple: SwiftUI `.smooth`, `.snappy`, `.spring(duration:bounce:)` для содержимого и `NSAnimationContext` для окна. Собственную физику пружины писать не требуется. Apple показывает эти готовые пресеты и поведение при изменении цели прямо во время движения в [Animate with springs](https://developer.apple.com/videos/play/wwdc2023/10158/). Совместное использование SwiftUI и AppKit разобрано в [Unifying your app’s animations](https://developer.apple.com/documentation/swiftui/unifying-your-app-s-animations).

Параметры ниже — стартовые настройки проекта, а не норматив Apple и не измеренная гарантия плавности:

| Действие | Предлагаемое готовое средство |
| --- | --- |
| Сдвиг соседних иконок | `.snappy(duration: 0.24, extraBounce: -0.03)` |
| Страница | `.smooth(duration: 0.26)`, направленный переход opacity + move |
| Папка | `.spring(duration: 0.28, bounce: 0.08)`, небольшой scale + opacity |
| Наведение | `.smooth(duration: 0.16)`, увеличение не более 1.04 |
| Появление окна | `NSAnimationContext`, alpha 0 → 1 за 0.20 с |
| Скрытие | alpha 1 → 0 за 0.14 с; `orderOut` только в completion |
| Reduce Motion | короткий fade; убрать пространственные пролёты и масштабирование |

Значения собрать в одном месте. Анимировать смену конкретной цели, а не весь каталог после поиска или фонового сканирования. Spring duration — параметр воспринимаемой длительности; завершение жизненного цикла нельзя строить на предположении, что любая пружина ровно через указанное число секунд уже закончилась.

## Перенос: что влияет на ощущение плавности

В исходной реализации анимация не может исправить две структурные проблемы: `ForEach` идентифицирует позиции строк/колонок, а не перемещаемые приложения; drop меняет постоянный массив только на отпускании. Нужны стабильный ID элемента и отдельная предварительная раскладка.

1. На старте сохранить исходный документ раскладки и ID элемента. Во время наведения менять только preview; сохранять и регистрировать Undo один раз после успешного drop.
2. Системный drag image должен следовать мыши без дополнительной пружины. В сетке оставить прозрачный placeholder нужного размера, соседей двигать штатной spring. Не показывать одновременно полную исходную иконку и drag image.
3. Для native drag использовать `NSDraggingSource`: [draggingSession(_:endedAt:operation:)](https://developer.apple.com/documentation/appkit/nsdraggingsource/draggingsession(_:endedat:operation:)) сообщает завершение сессии, включая результат операции. `operation == []` требует отката; успешный commit отмечается отдельно, чтобы завершение не сохранило данные повторно. Сбросить таймеры, hover, preview и временный ID единым идемпотентным методом.
4. Для внутреннего mouse-drag без `NSDraggingSession` явно обработать Escape, отпускание вне рабочей области и потерю активации. Один `.onDrop` на иконках не покрывает отмену.
5. Край экрана — широкая зона с выдержкой примерно 0.55 с, затем повтор не чаще 0.7 с. Это предлагаемые продуктовые значения. Хранить один отменяемый таймер; для AppKit tracking проверять run-loop mode. При выходе из зоны, завершении или отмене полностью сбрасывать ожидание. Не запускать новый таймер на каждом mouse move.
6. После перехода страницы drag image остаётся под курсором; координаты целевой ячейки рассчитываются из текущей геометрии. У исходного кода размеры ячейки с padding расходились с расчётом вместимости — обе величины должны иметь один источник.
7. Различать зону вставки и центральную зону создания папки; папку предлагать только после устойчивого наведения. Иначе изменение preview сдвигает цель под мышью и запускает дрожание между соседями. Стабильный ID цели важнее её текущего индекса.
8. Во время поиска безопаснее отключить reorder до наличия адресации по ID. При включении искать позиции в документе раскладки, а не применять индексы результатов поиска к полному массиву.

`matchedGeometryEffect` полезен при переходе между представлениями, но не заменяет корректный `ForEach` и не должен иметь две одновременные source-view с одним ID. Для простой перестановки достаточно стабильных элементов и анимации их layout.

## Окно, доступность и проверка

[NSAnimationContext](https://developer.apple.com/documentation/appkit/nsanimationcontext) предоставляет штатное выполнение группы анимаций. Окно подготовить до `orderFront`, не завершать процесс при Escape. При быстром повторном показе инвалидировать старое completion скрытия через token/состояние, иначе старый callback скроет уже открывшееся окно.

Учитывать [accessibilityReduceMotion](https://developer.apple.com/documentation/swiftui/environmentvalues/accessibilityreducemotion) и Reduce Transparency. Движение должно помогать видеть место вставки; подсветка, focus и доступные имена нужны независимо от эффектов.

Проверять Release на 60/120 Гц: перенос через строку, между страницами, в папку и обратно; отпускание на себя/фон/вне окна; Escape; быстрое hide → reopen. Измерить blocking work и длительные кадры через [Instruments для SwiftUI](https://developer.apple.com/videos/play/wwdc2025/306/). Успешная компиляция или тест массива не доказывают визуальную плавность.
