# Return Launchpad 3: реализация и проверка

Дата: 10 сентября 2026 года. Документ описывает новую реализацию; исходный аудит относится к прежней ревизии `2caf4d9`.

Завершающая проверка: 11 сентября 2026 года.

## Реализовано

| Этап исходного плана | Результат |
| --- | --- |
| Изолированная база | Удалены тесты, очищавшие рабочие defaults. Модель и persistence тестируются во временных каталогах; UI использует отдельный тестовый каталог |
| Полный каталог | Добавлены `/System/Applications`, вложенные Utilities, CoreServices/Applications и Finder; исключены агенты/helpers, дубли и собственное приложение |
| Быстрое окно | Метаданные сканируются вне главного потока; сохранённый каталог показывается до обновления; при закрытии окно скрывается, процесс сохраняется |
| Раскладка | Постоянные ID, версия схемы 2, атомарная последовательная запись, резервная копия legacy-порядка, Undo/Redo |

## Существенные решения

SwiftUI оставлен для поиска, навигации, настроек и оболочки. Сетка использует небольшой AppKit `NSView` со стабильными ячейками по ID и `NSDraggingSession`. Для ограниченного числа иконок на странице это даёт прямое управление геометрией, отменой, сменой страниц и изображением под указателем без отдельного diffable snapshot слоя `NSCollectionView`. Это уточнение рекомендации аудита, а не переход на новый стек. Владелец native drag не уничтожается при смене страницы.

Анимации выполняет Apple: SwiftUI `.smooth` / `.spring`, `NSAnimationContext.animate` для ячеек и `NSAnimationContext` для окна. Собственного физического движка нет. Единственная добавленная сторонняя библиотека — KeyboardShortcuts 3.0.1, MIT. Её точный commit закреплён в `Package.resolved`; уведомление о лицензии включено в приложение.

Состояние drag содержит неизменяемую исходную раскладку и отдельный preview. Отмена не выполняет запись. Подтверждение создаёт одну запись и одно действие Undo. Задержки наведения привязаны к токену сессии. При автоматическом открытии папки и смене страницы preview сразу адресует новый контейнер/страницу — даже если мышь после этого не двигалась.

Каталог хранит только Codable-метаданные. Иконки запрашиваются только для видимой страницы, по одной на проход главного run loop; они растеризуются до 256 × 256 и хранятся в NSCache с лимитом стоимости 32 МБ. Вызовы AppKit остаются на главном потоке. Чтение файлового каталога вынесено в отдельную задачу. Это уменьшает работу перед первым кадром, но не является утверждением о нулевой стоимости декодирования иконок.

Из старого хранения используется стандартная копия UserDefaults: v2 дублировала туда App Group данные. Неиспользуемый entitlement App Group удалён; App Sandbox сохранён. Повреждённый документ не перезаписывается. Отсутствующие приложения сохраняются в раскладке как ссылки, чтобы временно недоступный источник не разрушал папки.

Проверка подписанного приложения выявила отличие sandbox: домашние пути Foundation могут указывать на контейнер, а личная папка `~/Applications` требует разрешения. Путь определяется через `getpwuid_r`; доступ предоставляется только через системный выбор папки и сохраняется как read-only security-scoped bookmark. В настройках можно добавить и другие каталоги. Системные `/Applications` и `/System/Applications` не требуют этого шага. Основание: [Apple — Accessing files from the macOS App Sandbox](https://developer.apple.com/documentation/security/accessing-files-from-the-macos-app-sandbox).

## Проверки

Подробные результаты и скриншоты сохраняются в `.xcresult` в `build/TestResults`. Команды:

```sh
./scripts/test.sh
./scripts/test.sh --ui
./scripts/test.sh --performance
./create_release_dmg.sh
./scripts/profile.sh
```

Проверки модели охватывают точный порядок после движения вправо/влево, создание и расформирование папок, извлечение последнего ребёнка, запрет вложенных папок, повторные перемещения без потерь, неизменяемый original drag, отмену, поиск, Undo/Redo, сохранение, миграцию, повреждённые файлы, системные и вложенные каталоги, дедупликацию.

UI-сценарии используют настоящие события мыши: создание папки, извлечение на стрелку, смену страницы при удержании края, отпускание в краевой зоне, отмену drop вне сетки, повторный drag после отмены, Undo, поиск, настройки, скрытие без завершения процесса и сохранение папки после перезапуска.

Ввод тестового английского запроса выполняется через системное меню вставки с восстановлением буфера обмена, а Undo — через меню «Правка». Это исключает зависимость XCTest от активной русской раскладки; пользовательская раскладка не переключается. Проверка перехода при drag возвращается на первую страницу явно, поскольку длительное удержание края может пролистать несколько страниц.

Переключатели страниц используют стандартные SwiftUI Button с областью нажатия 28 × 28 pt и accessibility ID. Нижний отступ увеличен с 24 до 64 pt: у прежней позиции тестовые mouseDown не доставлялись окну; после переноса контролов выше воспроизводимые проверки физических кликов прошли. Отдельный UI-тест проверяет переход на вторую страницу и обратно. Межстраничный drag проверяется вместе с Undo, возвратом на первую страницу и перезапуском. Экспериментальные AppKit-кнопки и временная диагностика удалены.

Первый запуск неподписанного UI runner не прошёл bootstrap macOS. Скрипт тестов теперь использует локальную подпись и отдельный DerivedData. Также устранена нестабильность тестового окна при краткой активации внешнего test runner: это изменение только режима `--ui-testing`, пользовательская настройка не переопределяется.

## Границы проверки и выпуск

### Итоговый проверенный комплект

- Финальный функциональный прогон: **24 unit/integration + 10 UI-тестов, 0 ошибок**. Result bundle: `build/TestResults/20260911-003120.xcresult`; UI-сценарии заняли 92,3 секунды. Измеритель Launch Metric в этот прогон не включён.
- Установщик: `build/releases/20260911-002502/Return-Launchpad-3.0-universal.dmg`. Приложение содержит `x86_64` и `arm64`; `codesign --verify --strict` и `hdiutil verify` завершились успешно.
- SHA256: `35aae2c36b247d03481de0d742a568540978cc2b212c58efc52db70c66d44057`.
- Ручная проверка подписанной сборки: глобальная комбинация открывает окно из Finder; поиск находит Finder и Terminal; после выбора личной Applications каталог содержит 206 приложений и сохраняет доступ после перезапуска. Произвольные внешние каталоги можно подключать через настройки.
- Исправленный `scripts/profile.sh` завершился успешно: `build/Profiles/launch-20260911-003319.trace`. В TOC подтверждён точный путь `build/SignedTests/Build/Products/Debug/Return Launchpad.app/Contents/MacOS/Return Launchpad`, подключение по PID и завершение по 15-секундному лимиту. Это профиль тестового каталога после подключения, а не замер первого кадра или FPS.

### Ограничения

Локальная проверка проводится на Apple Silicon с macOS 26.6.2 и Xcode 26.3. Универсальный бинарник включает arm64 и x86_64, но запуск на физическом Intel Mac и macOS 15.5 требует соответствующих машин. Поведение Spaces, нескольких дисплеев, VoiceOver и 120 Гц не следует считать полностью подтверждённым только успешной компиляцией и автоматическими сценариями.

Метрика XCTest ApplicationLaunch включает запуск нового процесса под тестовой инфраструктурой. Её нельзя напрямую приравнивать к первому кадру или повторному показу уже работающего окна. Числа p95 и FPS из исходного аудита были целями, а не гарантией; для их подтверждения нужны отдельные измерения на эталонном устройстве.

Измерение Launch Metric вынесено в отдельную команду `--performance`. В одном из заключительных прогонов XCTest завис на третьем запуске. Односекундный `sample` показал 876/876 выборок главного потока в обычном ожидании событий AppKit (`mach_msg2_trap`), без выполнения кода приложения. Это свидетельствует о проблеме ожидания тестовой инфраструктуры в тот момент, но не является измерением плавности анимаций. Функциональный прогон сохраняет отдельный тест реального запуска и снимка интерфейса.

Первый профиль Instruments нельзя использовать как доказательство производительности новой сборки: запуск по bundle ID выбрал установленную копию с тем же идентификатором. Скрипт исправлен на запуск точного бинарника и подключение к его PID; он измеряет работу после подключения, а не полное время холодного запуска. Завершение по лимиту и читаемость trace проверяются отдельно.

Автозапуск предоставлен через SMAppService, но не включается автоматически на машине пользователя. Для его полноценной проверки приложение следует установить в Applications и явно включить переключатель. Запись горячей клавиши использует готовую проверку конфликтов библиотеки; стандартная комбинация — Control + Option + Пробел.

Локальный DMG подписан ad-hoc и сохраняет sandbox. Для публичного распространения без предупреждений Gatekeeper нужен сертификат Developer ID и notarization; скрипт поддерживает их через существующий Keychain profile. Автоматический workflow добавлен в репозиторий, но облачный запуск GitHub Actions не выполнялся из локальной сессии. Публикация релиза и отправка на notarization без настроенного профиля не происходят.

Удалённые до начала работы старые DMG из `release-versions` не восстанавливались и не включались в новые артефакты.


## Дополнение: версия 3.2

После проверки на реальном экране системная `NSDraggingSession` заменена внутренним переносом: локальный монитор мыши, отдельное изображение под указателем и прежняя модель предварительной раскладки. Это исключает передачу переноса системному механизму Spaces. Возврат из папки определяется по геометрии нативной кнопки внутри SwiftUI. Esc отменяет перенос, отпускание в заголовке отменяет изменение.

Пустой поиск: стрелки меняют страницы. Непустой поиск: автоматически выделяется первый результат, стрелки перемещают выделение, Enter запускает приложение. Окно использует повышенный уровень и `canJoinAllSpaces/fullScreenAuxiliary`; меню и Dock скрываются только на время показа, прежние presentation options восстанавливаются при скрытии.

Проверки 3.2: 27 unit-тестов; два целевых UI-сценария (создание папки/извлечение и перенос между страницами/Undo/перезапуск) прошли. Полный UI-набор повторно не запускался. Сборка Release — universal arm64/x86_64, локальная ad-hoc подпись.


## Дополнение: версия 3.3

Смена страницы во время переноса использует тот же переход Core Animation, что обычное перелистывание (0,24 с). Первая задержка у края — 0,65 с; повторная — 1,1 с. Уходящие страницы не участвуют в обработке мыши.

Для смены контейнера вместо горизонтального перелистывания используется масштабирование от положения папки с проявлением содержимого (0,32 с). При быстром отпускании над существующей папкой изображение переноса уменьшается и исчезает в её области (0,26 с), а модель сохраняется сразу. Удержание 0,8 с раскрывает папку; затем перенос продолжает работать внутри. Создание новой папки требует прежней задержки 0,55 с. Reduce Motion отключает пространственные переходы.

Короткие проверки: 27 unit-тестов; целевые UI-сценарии быстрого добавления/раскрытия папки и переноса между страницами/отмены. Для отмены тест нажимает кнопку интерфейса: генерация сочетания клавиш в XCTest вызвала системный запрос доступа у тестового runner.


## Исправление 3.3.1

Строка заголовка папки занимает постоянные 40 pt и появляется через opacity. Сетка сохраняет одну высоту и положение на главном экране и внутри папки, поэтому появление заголовка не вызывает дополнительного пересчёта геометрии во время zoom-перехода. Проверка: сборка Release universal и проверка DMG; полный UI-прогон не повторялся.


## Исправление 3.3.2

По записи пользователя обнаружен дополнительный источник вертикального движения: originY вычислялся из числа занятых рядов (8–26 pt). Теперь верхний отступ равен 8 pt независимо от содержимого. Прямое обновление frame выполняется без неявных Core Animation actions; явные переходы сохранены. Добавлен тест геометрии первого ряда для полной страницы, маленькой папки, повторного layout и возврата. 28 unit-тестов прошли; визуальная плавность новой сборки отдельно не проверялась.


## Исправления 3.4

Изменение строки поиска отменяет предыдущие переходы и перемещение ячеек, устанавливает конечную геометрию без неявной анимации и запускает общий opacity-переход 0→1 за 0,16 с. Hover больше не зависит исключительно от mouseExited: сбрасывается при смене содержимого, отсоединении ячейки, обновлении tracking areas и presentationID. Grid централизованно допускает только одну hovered-ячейку; mouseEntered сверяет действительное положение указателя и активность окна.

29 unit-тестов прошли, включая проверку fade без движения ячеек, эксклюзивности hover и его сброса при поиске/повторном показе. Длительный UI-прогон не запускался.


## Исправление 3.4.1

Обработка свободного фона перенесена в LauncherWindow.sendEvent. Нативные кнопки и редактируемый текст определяются через hit testing, SwiftUI-кнопки и вся поисковая панель — через явные геометрические области. Неинтерактивный фон в любой части окна скрывает лаунчер. Перенос, модальные окна и листы исключены. 29 unit-тестов прошли; целевой UI-тест проверил сохранение работы поиска/перелистывания и скрытие кликом слева от поиска без завершения процесса.


## Исправление 3.5.1

Клик по свободному фону теперь сначала закрывает открытую папку, сохраняя лаунчер на экране. На верхнем уровне следующий клик скрывает лаунчер. Обработка вынесена в AppManager.dismissBackground; активный перенос исключён. Новый тест проверяет оба шага и отсутствие преждевременного скрытия. 31 unit-тест прошёл.


## Извлечение из папки: 3.6

При начале переноса внутри папки кнопка возврата превращается в широкую зону 320 pt с надписью «Перетащите на главный экран». При наведении меняются цвет и текст на «Отпустите — на главный экран». Высота области заголовка остаётся 40 pt, сетка не сдвигается. Отпускание сопровождается уменьшением изображения переноса в направлении зоны; удержание сохраняет переход на главный экран для выбора позиции. Reduce Motion отключает цветовой и пространственный переходы. 31 unit-тест и целевой UI-сценарий создания папки/извлечения прошли.


## Аудит зоны извлечения: 3.6.1

Обнаружены две ошибки реализации 3.6: `NSViewRepresentable` получал только ссылку на модель и мог не обновлять native-кнопку при изменении drag; анимируемая ширина 32→320 pt перемещала кнопку и область приёма.

Теперь `isDragging` и название папки — явные значения входа representable. Native-кнопка конфигурируется и при создании, и при обновлении. Ширина постоянно 320 pt, соседние элементы занимают неизменное место; анимация изменения размеров удалена. В обычном режиме кнопка показывает название папки со стрелкой назад, во время переноса — приглашение извлечь иконку.

При завершении, отмене и удалении view сбрасываются подсветка, анимация цвета и hover-таймер. Кеш кнопки инвалидируется при смене folderID, чтобы не использовать уходящую кнопку другой папки.

32 unit-теста прошли, включая цикл обычное состояние → drag → hover → отмена → новый drag и проверку постоянного frame. UI-проверки охватывают извлечение из открытой папки и вход в папку удержанием внешней иконки.


## Заголовок папки: 3.6.3

В обычном режиме стрелка, название, редактирование и количество приложений образуют единый центрированный HStack. Ширина кнопки возврата зависит от длины названия и ограничена 260 pt; пустые балансирующие отступы удалены. При переносе соседние элементы исключаются из layout, остаётся центрированная зона шириной 320 pt. Изменение ширины не анимируется, высота заголовка 40 pt сохраняется. Проверка — сборка universal DMG.


## Заголовок без счётчика и обрезки: 3.6.5

Обычный заголовок отделён от native drop-зоны: SwiftUI HStack содержит стрелку с полным названием и кнопку редактирования, счётчик удалён. Ручной расчёт ширины текста отменён; используется естественный размер SwiftUI без многоточия. Отдельный UI-тест проверяет компактность и центрирование реальных элементов окна и сохраняет скриншот. Извлечение из папки проверено после разделения заголовка и drop-зоны.
